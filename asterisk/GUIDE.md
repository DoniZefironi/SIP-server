# Применение настроек станции на сервере

Для проверки голосового бота на действующей станции достаточно шагов из раздела
[«Голосовой пилот»](#голосовой-пилот).

Гайд переводит Asterisk на ВМ `siptrunk` (`10.1.0.148`) на сценарий из этой папки:
меню, очереди секторов, запись разговоров в три файла, сообщения, чёрный список, праздники,
доступ для сервиса телефонии. Займёт около получаса. Живых клиентов пока нет, поэтому
перезапуск станции ничего не ломает.

Проверено на Asterisk 22.5.2 (тот же пакет Ubuntu 26.04) с имитацией звонков: чёрный список,
нерабочий день, тишина в меню → сектор по умолчанию, очередь с лимитом двух ожидающих
(в том числе при одновременных звонках), ответ сотрудника с записью, режим «сразу сообщение».
Живыми телефонами не проверялось — это шаг 9.

## Что изменится

| Было | Станет |
|---|---|
| Сектора 1 и 2 звонят на `102`, 3–5 кладут трубку | Каждый сектор звонит на свой временный номер `101`–`105`, настоящие номера ставятся позже настройкой |
| Занято или не ответили — обрыв | До двух ожидающих на отдел без таймаута по умолчанию. Третий попадёт на голосовое сообщение |
| Три ошибки в меню — обрыв | Сектор 1 (Коммерческий) |
| Запись всего звонка с меню, на системный диск | Только разговор, три файла (общий, клиент, сотрудник), диск `/srv/recordings` |
| Сообщения без номера в имени файла | `ГГГГММДД-ЧЧММСС-номер-id.wav` в `/srv/recordings/messages` |
| Пароли `Password101!` | Случайные пароли — в MicroSIP их нужно будет ввести заново |

## 1. Вход и резервная копия

```
ssh siptrunk@10.1.0.148
```

Подключиться к серверу.

```
sudo cp -a /etc/asterisk /root/asterisk-backup-20261117
```

Полная копия текущих настроек станции. Из неё делается откат (раздел «Откат»).

## 2. Забрать файлы из репозитория

```
sudo git clone -b structure https://github.com/DoniZefironi/SIP-server.git /opt/savt-telephony
```

Скачать репозиторий в `/opt/savt-telephony`. Если репозиторий закрытый, git спросит логин
и токен GitHub. Если папка уже есть (репозиторий скачивался раньше), вместо этого:

```
cd /opt/savt-telephony && sudo git pull
```

## 3. Папки для записей и фраз

```
findmnt /srv/recordings
```

Проверка, что диск 200 ГБ подключён. В ответе должна быть строка с `/srv/recordings` и `ext4`.
Если ответ пустой — дальше не идти, диск не смонтирован.

```
sudo install -d -o asterisk -g asterisk -m 770 /srv/recordings/calls /srv/recordings/messages
sudo install -d -o asterisk -g asterisk -m 755 /var/lib/asterisk/phrases
```

Создать папки разговоров, сообщений и фраз. Владелец — пользователь `asterisk`, от его имени
работает станция. `770` — группа `asterisk` тоже может работать с файлами: в неё будет входить
сервис телефонии, он отдаёт записи фронту и удаляет пустые и просроченные (через год).

## 4. Фразы

Сейчас твои фразы лежат в системной папке звуков, в подпапке `custom`. Новый сценарий берёт
их из `/var/lib/asterisk/phrases` — там их не затрёт обновление пакета.

```
SRC=$(dirname "$(sudo find / -xdev -path '*custom*' -name 'greeting.wav' 2>/dev/null | head -1)")
echo "$SRC"
```

Найти папку с фразами. Команда должна напечатать путь, оканчивающийся на `/custom`.

```
sudo cp "$SRC"/* /var/lib/asterisk/phrases/
ls /var/lib/asterisk/phrases
```

Скопировать фразы и показать список. Нужны: `greeting`, `transfer`, `invalid`, `timeout`,
`after_hours`, `thank_you`. Фраза `fail_drop` больше не используется.

Нужно дозаписать три новые фразы:

| Файл | Текст (пример) |
|---|---|
| `queue_full` | «Все специалисты заняты. Оставьте сообщение после сигнала: имя, номер телефона и суть вопроса» |
| `queue_first` | «Все специалисты заняты, вы первый в очереди» |
| `queue_wait` | «Оставайтесь на линии, вам обязательно ответят» |

Пока их нет, станция в этих местах просто молчит, сценарий не ломается. Когда запишешь —
перекинуть на сервер так же, как прошлые (`scp`), и сконвертировать:

```
cd /var/lib/asterisk/phrases
sudo ffmpeg -i ~/queue_full.m4a -ar 8000 -ac 1 -c:a pcm_s16le queue_full.wav
```

`-ar 8000 -ac 1 -c:a pcm_s16le` — формат телефонии: 8 кГц, моно, 16 бит. Так же для
`queue_first` и `queue_wait`.

```
cd /opt/savt-telephony/asterisk
sudo cp extensions.conf queues.conf pjsip.conf pjsip_trunk.conf rtp.conf manager.conf /etc/asterisk/
```

Заменить настройки станции файлами из репозитория.

## 6. Пароли внутренних номеров

Пароли в репозиторий не кладём, поэтому файл с номерами создаётся на сервере:

```
sudo bash -c '
umask 077
: > /etc/asterisk/pjsip_users.conf
: > /root/sip-passwords.txt
for n in 101 102 103 104 105; do
  p=$(openssl rand -hex 8)
  printf "[%s](phone-endpoint)\nauth=auth%s\naors=%s\n\n[auth%s](phone-auth)\nusername=%s\npassword=%s\n\n[%s](phone-aor)\n\n" $n $n $n $n $n "$p" $n >> /etc/asterisk/pjsip_users.conf
  echo "$n $p" >> /root/sip-passwords.txt
done
chown asterisk:asterisk /etc/asterisk/pjsip_users.conf
'
sudo cat /root/sip-passwords.txt
```

Создаются номера `101`–`105` со случайными паролями из 16 символов. `umask 077` — файлы с
паролями может читать только владелец. Последняя команда показывает пароли. Номера `101`–`105` —
временные: по умолчанию сектор `N` звонит на `10N`, чтобы сценарий можно было проверить.
Настоящие телефоны секторов ставятся потом настройкой `sector_N_target` (раздел «Настройки»).

## 7. Доступ для сервиса телефонии (AMI)

```
sudo bash -c '
umask 077
s=$(openssl rand -hex 16)
printf "[telephony]\nsecret=%s\ndeny=0.0.0.0/0.0.0.0\npermit=127.0.0.1/255.255.255.255\nread=call,agent,user\nwrite=system\n" "$s" > /etc/asterisk/manager_users.conf
chown asterisk:asterisk /etc/asterisk/manager_users.conf
echo "$s" > /root/ami-secret.txt
'
```

Пользователь `telephony` подключается с самой машины, читает события звонков и очередей
и выполняет действия для управления настройками. Пароль сохранён в `/root/ami-secret.txt`,
он понадобится при запуске сервиса.

На уже настроенной станции добавьте `system` в `write=` существующей секции `[telephony]`.
Эта категория даёт сервису доступ к `DBGet`, `DBGetTree`, `DBPut`, `DBDel` и
`CoreShowChannels`. AMI остаётся на `127.0.0.1`. Примените права и переподключите API:

```sh
sudo asterisk -rx 'manager reload'
cd /opt/savt-telephony
sudo docker compose restart app
```

`manager reload` обновляет права для новых AMI-соединений. Уже открытая сессия API
сохраняет права, полученные при входе.

Установите обновлённый `extensions.conf` и выполните `sudo asterisk -rx 'dialplan reload'`,
чтобы сохранённые в панели номера и режимы очереди применялись к звонкам.

## 8. Перезапуск и проверка

```
sudo systemctl restart asterisk
```

Перезапустить станцию с новыми настройками.

```
sudo asterisk -rx "dialplan show reception" | tail -1
sudo asterisk -rx "queue show" | grep "has"
sudo asterisk -rx "pjsip show endpoints" | grep Endpoint:
sudo asterisk -rx "manager show users"
```

Что должно быть:
- сценарий загружен: строка вида `-= 4 extensions (… priorities) in 1 context. =-`;
- пять очередей `q1`–`q5`, у каждой `(max 2)`;
- пять номеров `101`–`105`, пока со статусом `Unavailable`: телефоны ещё не подключены;
- пользователь `telephony`.

```
sudo grep -E "ERROR|WARNING" /var/log/asterisk/messages | tail -20
```

Последние ошибки. Строки про `extensions.conf`, `queues.conf`, `pjsip` после времени
перезапуска — повод остановиться и прислать их мне.

```
sudo ufw status | grep -E "5060|10000"
```

Голос идёт по портам 10000–10199 (`rtp.conf`). В ответе должно быть правило на них
(или на более широкий диапазон с 10000). Если правила нет:

```
sudo ufw allow from 10.1.0.0/24 to any port 10000:10199 proto udp
```

## 9. Проверка звонками

Звонить «как клиент» удобнее с номера, который в проверке не участвует. В MicroSIP вместо `101`
подключить `105` с паролем из шага 6. Второе устройство (второй MicroSIP, Zoiper на
телефоне) подключить как `101`: на него по умолчанию звонит сектор 1. Сервер `10.1.0.148`,
транспорт UDP.

| Проверка | Как | Ожидаемо |
|---|---|---|
| Эхо | с `105` набрать `*43` | слышишь себя |
| Меню | с `105` набрать `777` | приветствие |
| Неверная цифра | в меню нажать `9` | `invalid`, меню заново |
| Тишина ×3 | молчать | `timeout` три раза, затем звонок на `101` (сектор 1) |
| Сектор | нажать `1` | `transfer`, звонит `101`; ответить — разговор |
| Никто не ответил | нажать `1`, на `101` не отвечать | `101` звонит 20 с, затем после паузы станция повторяет попытку. Клиент остаётся в очереди |
| Очередь заполнена | два клиента ждут в секторе 1, третий выбирает `1` | третий слышит `queue_full` и сигнал записи |
| Запись разговора | после разговора с `101` | `sudo ls -la /srv/recordings/calls` — три файла |
| Нерабочий день | см. ниже | `after_hours`, сигнал, запись |
| Сообщение | после сигнала сказать фразу | `sudo ls -la /srv/recordings/messages` — файл с номером `105` |

Включить «нерабочий день» на сегодня, чтобы проверить ветку вне рабочего времени,
и выключить обратно:

```
sudo asterisk -rx "database put savt-holiday $(TZ=Europe/Minsk date +%Y%m%d) 1"
sudo asterisk -rx "database del savt-holiday $(TZ=Europe/Minsk date +%Y%m%d)"
```

Прослушать запись на своём компьютере (в PowerShell на Windows):

```
scp siptrunk@10.1.0.148:/srv/recordings/messages/*.wav .
```

Если `scp` не пускает из-за прав — сначала на сервере
`sudo cp /srv/recordings/messages/*.wav ~/ && sudo chown siptrunk ~/*.wav`.

## Общие настройки станции

Фронт читает и сохраняет общие параметры через `GET` и `PUT /api/settings/telephony`.
Сохранение заменяет одну запись `savt/telephony_settings` в AstDB. Станция читает её при
начале нового звонка и перечитывает длительность попытки перед очередным дозвоном.

До первого сохранения значения берутся из прежних отдельных ключей AstDB или из
умолчаний сценария. В этом режиме продолжает работать ручная настройка:

```
sudo asterisk -rx "database put savt queue_wait 300"
```

| Ключ | По умолчанию | Что это |
|---|---|---|
| `work_days` | `mon-fri` | рабочие дни |
| `work_hours` | `0800-1659` | рабочие часы, без двоеточий |
| `menu_tries` | `3` | попыток в меню |
| `menu_timeout` | `6` | секунд ждать нажатия |
| `default_sector` | `1` | сектор после неудачных попыток (Коммерческий) |
| `queue_wait` | `0` | `0` — ждать без ограничения. Положительное значение задаёт таймаут очереди в секундах |
| `ring_time` | `20` | секунд звонить на телефон сектора за раз |
| `sector_N_target` | `PJSIP/10N` (временно) | куда звонит сектор N: настоящий телефон сектора, мобильный будет `PJSIP/+375…@life-trunk` |
| `sector_N_busy` | `queue` | `queue` — очередь; `message` — один дозвон и сразу сообщение |
| `msg_maxlen` | `120` | секунд на сообщение |
| `msg_silence` | `5` | секунд тишины, после которых запись сообщения останавливается |

Чёрный список и праздники — отдельные разделы базы:

```
sudo asterisk -rx "database put savt-blacklist 375291234567 1"
sudo asterisk -rx "database put savt-holiday 20261231 1"
sudo asterisk -rx "database show savt"
```

Для ожидания без таймаута передайте `queue_wait_seconds: null` через API. До первого
сохранения через API то же правило можно задать командой `database put savt queue_wait 0`.
Таймаут из карточки отдела имеет приоритет над общим значением.

Праздники из API и из CLI хранятся в одном семействе. Изменение вступает в силу при
проверке расписания нового звонка.

Номер в чёрном списке — только цифры, как его передаёт оператор (формат от life: ещё неизвестен).

Лимит очереди (2 ожидающих) — исключение: это `maxlen` в `/etc/asterisk/queues.conf`, только так
он надёжно работает при одновременных звонках. Поменять: исправить `maxlen=2` в файле и выполнить
`sudo asterisk -rx "queue reload parameters"`.

## Исходящие звонки сотрудников

После настройки транка оператора указать имя его PJSIP endpoint в AstDB.
В примере endpoint называется `life`, а SIP-учётная запись сотрудника — `104`.

```sh
sudo asterisk -rx 'database put savt outbound_trunk life'
sudo asterisk -rx 'database put savt staff_104_sector 4'
```

В `pjsip_users.conf` для сотрудников с правом внешней связи задать `context=from-staff`.
Контекст принимает международный набор с префиксом `+`. Если оператор требует
явное указание номера компании, задать согласованный номер в `savt/outbound_caller_id`.
После применения dialplan и настроек PJSIP звонок, инициированный такой учётной записью,
будет зарегистрирован в журнале вместе с результатом и записью разговора при ответе.

## Голосовой пилот

Позвоните с тестового мобильного на действующий номер life:) или наберите `778` на
внутреннем SIP-аппарате. Виртуальный оператор Ася предложит назвать номер объекта
или шкафа. Можно сказать «без номера» или сразу задать вопрос. Если Ася повторит
номер, подтвердите его словом «да». При отсутствии совпадения она предложит задать вопрос.

После сигнала можно подождать до пяти секунд перед началом речи. Когда абонент
заговорил, обработка начинается после двух секунд тишины или нажатия `#`. Если
реплика превышает предел распознавания, Ася дожидается паузы и просит сформулировать
вопрос короче. Когда реплика отправлена на обработку, Ася коротко говорит «Тактактак»,
если результат ещё готовится.
После ответа дождитесь следующего сигнала, чтобы задать уточнение или новый вопрос.
Бот использует две предыдущие пары вопросов и ответов в пределах звонка.

В рабочее время нажмите `0` или скажите «оператор» после сигнала для перевода звонка.
В нерабочее время скажите «оставить сообщение» или нажмите `0`. Чтобы завершить
диалог после ответа, нажмите `1` или скажите «вопрос решён». Если в базе нет точного
ответа на вопрос, Ася говорит об этом и передаёт звонок в штатный сценарий.

Когда Ася распознаёт сообщение о пожаре, дыме, ударе током или другой явной угрозе,
она советует уйти в безопасное место и сразу набрать `112`. После фразы звонок
завершается и учитывается во «Входящих» с результатом `emergency_referred`.
Опасная неисправность без явной угрозы передаётся в действующий маршрут специалиста.
В нерабочее время этот маршрут предлагает голосовое сообщение. В обоих случаях
вопрос обрабатывается в телефонии до обращения к базе знаний.
[Экстренные номера в Беларуси](https://travel.state.gov/en/international-travel/travel-advisories/belarus.html)

Бот отвечает на общие вопросы. На линии life:) режим пилота позволяет включить его для
одного выбранного номера звонящего перед запуском по графику и отделам. Если абонент
подтвердил, что ответ помог, звонок попадёт во «Входящие» с результатом `bot_answered`.

На ВМ обновите приложение из каталога репозитория. Для синтеза у сервисного аккаунта
SpeechKit должна быть роль `ai.speechkit-tts.user` или более широкая роль, включающая её.
Используются текущие `TELEPHONY_SPEECHKIT_API_KEY` и `TELEPHONY_SAVTASSIST_API_SECRET`.
[Роли SpeechKit](https://aistudio.yandex.ru/en/docs/ai-studio/security/#ai-speechkit-tts-user)

```sh
cd /opt/savt-telephony
sudo docker compose up -d --build app
sudo docker compose exec -T app python -m app.services.voice_bot /tmp/savt-bot-prompts </dev/null
prompts=$(mktemp -d)
sudo docker compose cp app:/tmp/savt-bot-prompts/. "$prompts/"
sudo install -o root -g asterisk -m 0644 "$prompts"/bot_*.wav /var/lib/asterisk/phrases/
agi_dir=$(sudo asterisk -rx 'core show settings' |
  sed -n 's/^[[:space:]]*AGI Scripts directory:[[:space:]]*//p')
test -n "$agi_dir" &&
  sudo mkdir -p -- "$agi_dir" &&
  sudo install -o root -g asterisk -m 0755 asterisk/savt-voice-bot.py "$agi_dir/"
```

Скопируйте общий секрет из контейнера в файл, который читает пользователь Asterisk.
Команда записывает секрет в файл без вывода на экран.

```sh
sudo -v
sudo docker compose exec -T app python -c \
  'from app.config import get_settings; print(get_settings().savtassist_api_secret.get_secret_value().strip())' |
  sudo sh -c '
    set -eu
    IFS= read -r secret
    test -n "$secret"
    file=$(mktemp /etc/asterisk/.savt-voice-bot.XXXXXX)
    trap "rm -f -- \"$file\"" EXIT
    printf "%s\n" "$secret" > "$file"
    chown root:asterisk "$file"
    chmod 0640 "$file"
    mv -f -- "$file" /etc/asterisk/savt-voice-bot.secret
  '
```

В `/etc/asterisk/extensions.conf` примените изменения в `[from-trunk]`, `[reception]`,
`[sector]` и `[sub-department-route]`. Добавьте маршрут `778` в `[from-internal]` и
контекст `[voice-bot-pilot]` из [текущего сценария](extensions.conf). Перечитайте
dialplan и проверьте маршруты.

```sh
sudo asterisk -rx 'dialplan reload'
sudo asterisk -rx 'dialplan show from-trunk'
sudo asterisk -rx 'dialplan show reception'
sudo asterisk -rx 'dialplan show sector'
sudo asterisk -rx 'dialplan show 778@from-internal'
sudo asterisk -rx 'dialplan show voice-bot-pilot'
```

Для проверки с мобильного укажите его полный входящий Caller ID без плюса. Замените
`375XXXXXXXXX` на номер **того, кто звонит**, в том же виде, в котором АТС получает
его от оператора. С клиентской линии звоните на действующий номер life:).

```sh
sudo asterisk -rx 'database put savt voice_bot_test_caller 375XXXXXXXXX'
```

Задайте вопрос, ответ на который есть в опубликованном FAQ. Затем позвоните ещё раз,
нажмите `0` после сигнала и проверьте переход в обычный сценарий. После теста снимите
привязку к мобильному номеру.

```sh
sudo asterisk -rx 'database del savt voice_bot_test_caller'
```

### Запуск по графику и отделам

После проверки ответа на вопрос из FAQ и перехода к сотруднику по вопросу вне базы
включите голосовой сценарий для входящей линии.

```sh
sudo asterisk -rx 'database put savt voice_bot_enabled 1'
```

- Вне рабочего времени, включая праздники, бот предлагает задать вопрос сразу. Если
  ответ не помог, можно оставить голосовое сообщение.
- В рабочее время сначала открывается меню. При выборе наладки или разработки бот
  предлагает задать вопрос. Если ответ не помог, звонок идёт в очередь выбранного отдела.
- При выборе остальных отделов звонок сразу идёт в их очередь.

Наладка и разработка определяются по привязкам отделов из Битрикс24. В исходном меню
это кнопки `2` и `3`. Настройка действует со следующего звонка и имеет приоритет над
прямым пилотом для отдельного номера. Команда ниже выключает маршрутизацию через бота
по графику и отделам.

```sh
sudo asterisk -rx 'database put savt voice_bot_enabled 0'
```

### Обновление голосового диалога

После `git pull` запустите обновление на ВМ.

```sh
cd /opt/savt-telephony
sudo bash scripts/deploy_voice_bot.sh
```

Скрипт обновляет контейнер `app`, устанавливает WAV и AGI в отдельные пути для
текущей версии и проверяет доступ к API с текущим секретом Asterisk. Затем он сохраняет
резервную копию и заменяет только контекст `[voice-bot-pilot]` в рабочем dialplan.
Если Asterisk не загрузит новый маршрут, скрипт восстановит предыдущий dialplan.

После сообщения «Голосовой бот установлен» позвоните на номер life:) и выберите
наладку или разработку. Ася представится и предложит назвать номер объекта или шкафа.
Подтвердите номер и задайте два вопроса подряд, затем скажите «оператор».
В выводе `sudo docker compose logs app` строки `voice turn` показывают длительность
распознавания, поиска и синтеза в миллисекундах.

## Что знать

- Если звонок не дошёл до разговора (сообщение, очередь), в `calls` остаются пустые файлы
  по 44 байта. Сервис будет их убирать.
- Запись сообщения в ветке «очередь заполнена» не попадает в файл разговора.
- Срок хранения записей не решён. Объём — около 1 МБ на минуту для каждого из трёх файлов.
