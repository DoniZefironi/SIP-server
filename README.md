# Телефония SAVT

Сервис на Python (FastAPI) рядом со станцией Asterisk. Слушает события станции, складывает их
в базу и отдаёт по HTTP. Меню, очереди и запись делает сам Asterisk; если сервис остановлен,
звонки идут как обычно.

Полное описание задачи — в [telephony-service-brief.md](telephony-service-brief.md).

## Что уже есть

- Подключение к станции по AMI (поток событий Asterisk, TCP-порт 5038) с переподключением при обрыве.
- Настройки станции в [asterisk/](asterisk/): сценарий, очереди, SIP, AMI и гайд по применению.
- Таблица `call_events`: события звонков (новый канал, вызов, ответ, очередь, отбой)
  и этапы сценария станции (`SavtCall`, `SavtRecording`, `SavtMessage`).
- `GET /health` — состояние сервиса, базы и связи со станцией (200 или 503).
- `GET /api/events?limit=50&linkedid=…` — последние события, для отладки.
- Журнал звонков: `GET /api/calls` (фильтры `sector`, `outcome`, `caller`, `date_from`, `date_to`),
  `GET /api/calls/{id}`, записи `GET /api/calls/{id}/audio/{mix|client|staff|message}`.
- Очередь `recording_jobs`: готовый WAV разговора или голосового сообщения завершённого звонка
  ставится в очередь один раз, в том числе если файл появился после отбоя. Проверка проходит
  при запуске и затем каждые 15 секунд, пока включена `TELEPHONY_RECORDING_QUEUE_ENABLED`.
- Асинхронное распознавание через Yandex SpeechKit. `GET /api/calls/{id}` отдаёт статус и текст.
  Для разговора с двумя доступными дорожками текст содержит реплики с таймкодами. Для звонка со
  статусом `bot_answered` вторая дорожка подписывается «Ася».
  Голосовые сообщения и записи с одной дорожкой сохраняются обычным текстом.
  Для запуска задать `TELEPHONY_SPEECHKIT_ENABLED=true` и `TELEPHONY_SPEECHKIT_API_KEY` в `.env`.
  После включения сервис отправляет WAV до 60 МБ из очереди, включая накопленные задачи.
  Если SpeechKit мог принять файл, но идентификатор операции не сохранился, задача переходит
  в `failed`, чтобы избежать автоматической повторной загрузки.
- Выжимка через YandexGPT на основе сохранённой расшифровки. `GET /api/calls/{id}` отдаёт
  её статус, суть обращения, договорённости, следующие действия и однозначно распознанный код
  сделки. Для запуска задать `TELEPHONY_YANDEXGPT_ENABLED=true`, `TELEPHONY_YANDEXGPT_FOLDER_ID`
  и `TELEPHONY_YANDEXGPT_API_KEY` в `.env`. Обрабатываются и накопленные расшифровки.
  Для звонков со статусом `bot_answered` выжимка формируется в карточке звонка.
- Доставка выжимок в Bitrix24 через входящий вебхук с правами `crm` и `im`.
  В личном сообщении сотруднику указывается имя со ссылкой на карточку звонящего
  либо номер, если CRM-карточка не найдена.
  `GET /api/calls/{id}` показывает адресатов, статус каждой отправки и ID записи в Bitrix24.
  Перед включением `TELEPHONY_BITRIX_ENABLED` заполнить `TELEPHONY_BITRIX_WEBHOOK_URL`
  и назначить резервных получателей по секторам при необходимости. При включении обрабатываются
  и накопленные выжимки. Если факт отправки после таймаута не удалось подтвердить по истории,
  доставка получает статус `uncertain` для ручной сверки.
- Обслуживание раз в час: удаление пустых записей, записей старше года
  (`TELEPHONY_RECORDINGS_RETENTION_DAYS`) и сырых событий старше 90 дней.
- Приведение номеров к виду `+375291234567`.

API слушает только на самой машине. Прокси предоставляет доступ по HTTPS, API проверяет
учётную запись и роль при каждом обращении к данным панели.

## Авторизация и роли

Приложение создаёт таблицы авторизации при запуске контейнера. Первого администратора
создаёт оператор сервера в интерактивном терминале после запуска `app`.

```sh
cd /opt/savt-telephony
sudo docker compose up -d --build --no-deps app
sudo docker compose exec app python -m app.create_admin admin
```

Пароль вводится дважды без отображения. Логин содержит от 3 до 64 латинских букв, цифр,
точек, дефисов или подчёркиваний и начинается с буквы или цифры. Регистр логина игнорируется.
Пароль содержит от 8 до 128 символов и хранится в виде хеша Argon2id.

- `viewer` — история, карточки и WAV звонков, статистика, список отделов для фильтров.
- `manager` — права `viewer`, просмотр карточек отделов и изменение настроек АТС, календаря
  и маршрутов отделов.
- `admin` — права `manager`, пользователи, события АТС и документация API.

### Вход на фронте

Использовать относительные URL на одном HTTPS-домене с интерфейсом. Прокси передаёт
`Cookie`, `Set-Cookie`, `Range` и `Cache-Control`. Для лимита попыток прокси передаёт адрес
клиента, например через `proxy_set_header X-Forwarded-For $remote_addr;` при подключении
прокси с loopback. Публичный `/health` предназначен для проверки сервиса. Внутренние
маршруты `/internal/telephony/` обслуживают интеграции по `X-Telephony-Secret`.

- `POST /api/auth/login` принимает `{"username":"admin","password":"…"}`. В ответе
  профиль `id`, `username`, `role`, `is_active`, `created_at` и две `HttpOnly` cookie.
- `GET /api/auth/me` возвращает профиль по текущей сессии. При `401` вызвать
  `POST /api/auth/refresh` один раз и повторить исходный запрос после успеха. Если
  обновление вернуло `401`, показать форму входа. Обновление сессии сериализовать,
  в том числе между вкладками. Повторное предъявление использованной refresh-cookie
  отзывает сессию.
- `POST /api/auth/logout` отзывает сессию и очищает cookie. Для своего пароля использовать
  `POST /api/auth/change-password` с `current_password` и `new_password`. После смены пароля
  выполняется новый вход. Изменение пароля, роли или статуса из админки также отзывает сессии.
- `GET /api/auth/users?limit=50&offset=0` показывает список аккаунтов. `POST /api/auth/users`
  создаёт аккаунт по `username`, `password` и `role`. `PATCH /api/auth/users/{id}` принимает
  изменяемые поля `role`, `is_active`, `password`. Для управления кнопками использовать
  `role` из профиля. Сервер проверяет роль самостоятельно.
- Для `POST`, `PUT`, `PATCH` и `DELETE` отправлять `X-SAVT-CSRF: 1`. Для JSON также
  передавать `Content-Type: application/json`. Записи можно проигрывать по существующим
  относительным URL. Браузер приложит access-cookie к запросу WAV.

Access-токен живёт до 10 минут. Сессия закрывается после суток без обновления или через
7 дней после входа. PostgreSQL хранит хеши токенов и счётчики входа. Лимиты на 15 минут
составляют 10 попыток на логин и 60 на IP. Активные блокировки кэшируются в памяти процесса.
При `429` время ожидания передаётся в `Retry-After`.

```
app/
  main.py          запуск сервиса и фоновой задачи AMI
  config.py        настройки из переменных окружения (TELEPHONY_*)
  ami/client.py    клиент AMI
  ami/events.py    какие события сохраняем
  api/             HTTP-эндпоинты
  db/              модели и подключение к PostgreSQL
  services/        журнал звонков, номера, обслуживание

```

## Стенд для фронтенда

Из корня репозитория с Python 3.13, uv и Docker запустить:

```sh
docker compose -f compose.frontend.yml up -d --wait
uv run --locked python -m scripts.frontend_demo
```

API будет доступен на `http://127.0.0.1:18081`, Swagger на [/docs](http://127.0.0.1:18081/docs),
контракт на [/openapi.json](http://127.0.0.1:18081/openapi.json). Стенд использует отдельную
базу на порту `15432`, выполняет миграции и заполняет её тестовыми звонками. Логин и новый
пароль для локального стенда выводятся в терминал при запуске. Внешние
интеграции отключены. Данные остаются между запусками и сохраняют те же ID.

| Карточка | Что проверить |
| --- | --- |
| `1` | Разговор, общая и две отдельные WAV-дорожки, диалог с таймкодами, выжимка и доставка в Bitrix24 |
| `2` | Голосовое сообщение и обычный текст расшифровки |
| `3` | Звонок завершился в очереди, запись отсутствует |
| `4` | Расшифровка в обработке |
| `5` | Расшифровка завершилась ошибкой |
| `6` | Звонок ещё идёт |
| `7` | Исходящий звонок с записью и инициатором |

В WAV используются короткие тоны для проверки загрузки и перемотки. Тексты, выжимки
и статусы доставки заданы как примеры. `GET /health` для стенда возвращает `ami: "disabled"`.

### Подключение интерфейса

- `GET /api/calls?limit=50&offset=0` отдаёт `{ items, total }`. Фильтры `sector`, `outcome`,
  `caller`, `date_from` и `date_to` применяются на сервере. `date_from` включается в диапазон,
  `date_to` исключается. Передавать даты в ISO 8601 с часовым поясом.
- Поиск по номеру передаётся в `caller`. Поддерживаются полный номер, часть номера и ввод
  с пробелами, скобками и дефисами. Например, `?caller=1234567` найдёт `+375291234567`.
  При изменении поиска сбросить `offset` на `0`, при очистке поля опустить `caller`.
- Для вкладок истории передавать `tab=incoming` для принятых входящих, `tab=outgoing`
  для исходящих сотрудника, `tab=missed` для завершённых входящих без ответа. Во вкладке
  пропущенных `voicemail=true` выбирает звонки с голосовым сообщением, `voicemail=false`
  выбирает звонки без сообщения. Для вкладки «Все» внутри пропущенных опустить `voicemail`.
- `GET /api/calls/counts` возвращает `incoming`, `outgoing`, `missed`,
  `missed_with_voicemail` и `missed_without_voicemail`. Передавать те же `date_from`, `date_to`,
  `sector` и `caller`, что в списке. Счётчики считаются по всему диапазону.
- Для колонки «Отдел» использовать `sector_name` и `sector_number`. Номера задаются
  через `TELEPHONY_SECTOR_NUMBERS`, например `{"4":"+375..."}`. Для колонки «Сотрудник»
  использовать `employee_name`, затем `employee_number` или прочерк. `employee_number`
  содержит телефон без SIP-транка либо внутренний добавочный номер.
  Исходные адреса станции возвращаются в `initiated_by` и `answered_by`.
  Сопоставление с именами задаётся через `TELEPHONY_EMPLOYEE_NAMES`. У исходящих поле
  `caller` содержит номер клиента, которому позвонили.
- `voicemail_left` фиксирует факт записи голосового сообщения после регистрации
  готового WAV очередью обработки. `has_message` показывает, доступен ли файл сейчас.
- `GET /api/calls/{id}` отдаёт поля звонка, расшифровку, выжимку и список доставок
  в Bitrix24 с отдельным статусом по каждому адресату. Активный звонок определяется по
  `ended_at: null`. Поля обработки могут быть `null`, пока задача ещё не создана.
- По клику на номер в колонке «Клиент» вызвать `GET /api/calls/{id}/contacts`. API возвращает
  `{"items":[{"id":8903,"name":"Имя контакта","url":"https://…/crm/contact/details/8903/"}]}`.
  При одном совпадении открыть `url`, при нескольких показать имена со ссылками, при пустом
  списке сообщить, что контакт по номеру не найден. Поиск использует существующую сессию панели
  и вебхук `TELEPHONY_BITRIX_WEBHOOK_URL` с правом чтения CRM (`crm`).
- `GET /api/calls/{id}/audio/{kind}` отдаёт `audio/wav`. `kind` принимает `mix`, `client`,
  `staff` или `message`. Для `mix` и `message` используются флаги `has_recording` и
  `has_message`. Для отдельных дорожек обработать `404`. Через прокси передать `Range` и
  `If-Range` на API и сохранить статус и заголовки `Accept-Ranges`, `Content-Range`,
  `Content-Type` и `Content-Length` в ответе.
  Если звонок начал бот, `mix` содержит разговор с Асей и последующий разговор с сотрудником
  в одном файле. `client` содержит голос клиента, `staff` — то, что слышал клиент.

Во фронтенде использовать относительные URL через прокси на том же домене. При
локальной разработке адрес API для прокси — `http://127.0.0.1:18081`. Для API на ВМ можно
открыть SSH-туннель на компьютере, где запущен прокси:

```sh
ssh -N -L 18080:127.0.0.1:8000 siptrunk@10.1.0.148
```

С этим туннелем адрес API для прокси — `http://127.0.0.1:18080`. Браузер открывает интерфейс
по HTTPS, а прокси обращается к API через туннель.

Остановка стенда — `Ctrl+C` в окне API, затем `docker compose -f compose.frontend.yml down`.

### Статистика

Оба отчёта принимают `date_from`, `date_to` и необязательные `sector` и `caller`. Границы задаются
в ISO 8601 с часовым поясом. Начало периода включается, конец исключается.

- `GET /api/statistics/calls` отдаёт итоги в `totals` и данные графика в `buckets`.
  `group_by` принимает `day`, `week` или `month`. По умолчанию используется `day`.
  `bucket_start` — дата начала календарного интервала по Минску. Неделя начинается
  в понедельник. Для интервалов без звонков фронт ставит нули. `total` — сумма
  `incoming`, `outgoing` и `missed`. Для пропущенных есть разбивка
  `missed_with_voicemail` и `missed_without_voicemail`.
- `GET /api/statistics/callers` возвращает `{ items, total }`. Каждая строка содержит
  номер клиента `caller`, количество входящих `calls`, количество пропущенных
  из них `missed` и время последнего вызова `last_called_at`. Строки идут от самых
  частых номеров к самым редким, при равных значениях сверху идут недавние.
  Для пагинации используются `limit` и `offset`. В отчёт попадают звонки
  с распознанным номером, принятые сотрудником или завершённые без ответа.

### Отделы

- `GET /api/departments` отдаёт дерево отделов плоским списком `items` с `parent_id`,
  количеством сотрудников, настройками маршрута и состоянием звонков. Поле `sectors`
  содержит номера секторов Asterisk для выбора в настройках.
  В список входят коммерческий сектор, бухгалтерия, разработка ПО, наладка
  и проектирование. Если родитель отсутствует
  в этом списке, подразделение возвращается с `parent_id: null`.
- Для фильтра «Отдел» в истории и статистике брать название из `items[].name` и передавать
  `items[].settings.sector` в параметре `sector`. Выбирать можно отделы с
  `directory_present: true` и настроенным `settings.sector`. Для «Все отделы» опустить `sector`.
- `GET /api/departments/{id}` добавляет список `employees` с именами, должностями и фото.
  Справочник Bitrix24 обновляется при запросах с кэшем на 60 секунд. `directory_present: false`
  означает, что в Asterisk осталась привязка к отделу, исчезнувшему из справочника.
- `PUT /api/departments/{id}/settings` сохраняет маршрут. Пример тела запроса
  `{"sector":4,"primary_number":"+375291234567","additional_numbers":[],"busy_mode":"queue","queue_wait_seconds":120}`.
  Основной номер используется для дозвона. Дополнительный можно назначить основным
  в этом же редакторе. Режим `message` переключает звонок на голосовое сообщение после дозвона,
  `queue` использует очередь. `queue_wait_seconds: null` наследует настройку станции,
  где ожидание по умолчанию без таймаута. В очереди каждого отдела помещаются двое ожидающих.
  Занятый другим отделом сектор даёт `409`.
- `DELETE /api/departments/{id}/settings` снимает привязку и возвращает `204`. Сектор
  снова работает с настройками AstDB, заданными для него до привязки отдела.
- `call_status` принимает `in_call`, `idle`, `unconfigured` или `unknown`.
  `active_calls` показывает число активных разговоров, когда статус известен. При
  `settings_available: false` справочник доступен, а сохранение привязки недоступно.

Для запуска установите `TELEPHONY_BITRIX_DIRECTORY_ENABLED=true` и добавьте вебхуку из
`TELEPHONY_BITRIX_WEBHOOK_URL` права `department` и `user_brief`. Маршрут в карточке
хранится по ID отдела в AstDB. Для чтения и записи маршрутов [настройте AMI](asterisk/GUIDE.md#7-доступ-для-сервиса-телефонии-ami)
и загрузите обновлённый `extensions.conf`. Основной номер отдела набирается через PJSIP-транк
из `outbound_trunk`. Если он отсутствует, для маршрута вида `PJSIP/номер@транк` станция
использует транк из `sector_N_target`. Для локального дозвона действует телефон сектора
из `sector_N_target` или тестовый `PJSIP/10N`.

### Общие настройки АТС

`GET /api/settings/telephony` возвращает действующие значения Asterisk.
`PUT /api/settings/telephony` принимает и возвращает весь объект:

```json
{
  "work_days": ["mon", "tue", "wed", "thu", "fri"],
  "opens_at": "08:00",
  "closes_at": "17:00",
  "menu_attempts": 3,
  "menu_timeout_seconds": 6,
  "default_sector": 1,
  "queue_wait_seconds": null,
  "ring_time_seconds": 20,
  "voicemail_max_seconds": 120,
  "voicemail_silence_seconds": 5
}
```

Время задаётся по Минску. `closes_at` — первая нерабочая минута. Для конца дня
передайте `24:00`. Интервал может пересекать полночь, а рабочий день проверяется
по текущей календарной дате. `default_sector` принимает значения от 1 до 5.
`queue_wait_seconds: null` означает ожидание без таймаута. В карточке отдела
`queue_wait_seconds: null` наследует общее значение. Два места в очереди задаются
через `maxlen` в `queues.conf`.

- `GET /api/settings/holidays` возвращает `{"dates":["2026-12-31"]}`.
- `PUT /api/settings/holidays/{day}` добавляет дату, `DELETE` удаляет её. Оба запроса
  отвечают `204` без тела, в том числе при повторе. Дату передавать как `YYYY-MM-DD`.
- `422` означает ошибку валидации. При `503` станция не подтвердила операцию.
  После ошибки сохранения перечитайте значения, прежде чем повторять запрос.

Для запуска загрузите обновлённый `extensions.conf` и примените права AMI из
[гайда Asterisk](asterisk/GUIDE.md#7-доступ-для-сервиса-телефонии-ami). Общий пакет
сохраняется в `savt/telephony_settings` и имеет приоритет над прежними ключами AstDB.
До первого сохранения API и сценарий читают прежние значения. Праздники читаются и
пишутся в существующее семейство `savt-holiday`.

### Поиск объекта или шкафа для звонка

Общий секрет с SavtAssist задаётся в `TELEPHONY_SAVTASSIST_API_SECRET` на стороне телефонии
и в `TELEPHONY_API_SECRET` на стороне SavtAssist. `TELEPHONY_SAVTASSIST_BASE_URL` по умолчанию
равен `https://helper.savt.by`. Сервис отправляет запросы только по HTTPS.

Внутренний запрос `POST /internal/telephony/calls/{linkedid}/resolve-object` принимает
`{"number":"25_125_2","kind":"cabinet"}` и заголовок `X-Telephony-Secret`. `linkedid` —
идентификатор канала Asterisk, `kind` можно опустить. Сервис сохраняет ответ SavtAssist
(`found`, `ambiguous` или `not_found`) в карточке активного звонка. В
`GET /api/calls/{call_id}` он доступен в поле `object_lookup`.

Если найденная карточка содержит `bitrix_deal_id`, выжимка отправляется в эту сделку.
При сбое SavtAssist запрос возвращает `502`. Карточка звонка и доставка продолжают
использовать ранее сохранённые данные.

### Общие вопросы для голосового бота

Внутренний запрос `POST /internal/telephony/answer-question` принимает
`{"question":"Где найти инструкцию по подключению шкафа?"}` и тот же заголовок
`X-Telephony-Secret`. Номер объекта, номер шкафа и идентификатор звонка не требуются.

- `200`, `status: "answered"` — в `answer` короткий текст для озвучки.
- `200`, `status: "needs_operator"` — `answer` равен `null`. Бот может предложить
  соединение с сотрудником в рабочее время или голосовое сообщение вне него.
- `502` — SavtAssist недоступен или вернул некорректный ответ. Бот может использовать
  тот же резервный сценарий.

Для Asterisk есть внутренний `POST /internal/telephony/answer-audio` с тем же заголовком
`X-Telephony-Secret`. Принимает тело WAV PCM, 8 кГц, моно, 16 бит. Возвращает `200`
со звуком в том же формате, `204` при тишине или `needs_operator`, `502` при сбое
внешнего сервиса и `504` при истечении общего времени обработки. Проверка голосом
доступна с мобильного через линию оператора и через внутренний номер `778` после
[установки пилота](asterisk/GUIDE.md#голосовой-пилот).

При включении [маршрутизации по графику и отделам](asterisk/GUIDE.md#запуск-по-графику-и-отделам)
бот первым отвечает вне рабочего времени и после выбора наладки или разработки в рабочее время.
Звонок, который обработала Ася, получает `outcome: "bot_answered"` («Принято ботом»),
даже если клиент положил трубку без подтверждения. Если сотрудник ответил на перевод,
результат будет `answered` («Принято»). Оба результата учитываются во входящих.

Голосовой диалог распознаёт реплику через `POST /internal/telephony/voice-turn` и получает
озвученный ответ через `POST /internal/telephony/voice-answer`. AGI держит две последние
пары реплик для уточняющих вопросов. Приветствия, паузы вроде «так-так-так» и команды
«оператор» и «вопрос решён» обрабатываются без обращения к базе знаний.
«Тактактак» звучит, когда после распознавания вопроса ответ ещё готовится.
Если точного ответа нет, Ася предлагает задать другой вопрос или нажать ноль.
Перед вопросами Ася может распознать номер объекта или шкафа и попросить подтвердить его.
Подтверждённый номер проверяется в SavtAssist, а результат сохраняется в `object_lookup`
карточки активного звонка для маршрутизации выжимки в Битрикс24.

## Запуск на рабочем компьютере (без Asterisk)

Нужны Python 3.13, uv и Docker.

```
copy .env.example .env
```

В `.env` задать `TELEPHONY_DB_PASSWORD` и поставить `TELEPHONY_AMI_ENABLED=false`. Затем:

```
uv sync
docker compose up -d db
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

Проверка: открыть http://127.0.0.1:8000/health и http://127.0.0.1:8000/docs.

Тесты и проверка кода:

```
uv run pytest
uv run ruff check .
```

## Запуск на сервере (ВМ siptrunk)

На ВМ проверены тестовые звонки через PJSIP, запись и API. Проверка входящих с внешней
линии потребуется после подключения SIP-транка.

Для исходящих звонков через Asterisk см. [настройку SIP-учётных записей сотрудников](asterisk/GUIDE.md#исходящие-звонки-сотрудников).

**1. Станция.** Сначала применить настройки Asterisk по [asterisk/GUIDE.md](asterisk/GUIDE.md):
там же скачивается репозиторий в `/opt/savt-telephony` и создаётся пользователь AMI `telephony`
(пароль — в `/root/ami-secret.txt`).

**2. Сервис.**

```
cd /opt/savt-telephony
sudo cp .env.example .env
sudo cat /root/ami-secret.txt
sudo nano .env
```

В `.env` задать:
- `TELEPHONY_DB_PASSWORD` — свой случайный пароль, например из `openssl rand -hex 16`;
- `TELEPHONY_AMI_SECRET` — пароль, который показала команда `sudo cat /root/ami-secret.txt`;
- `TELEPHONY_ASTERISK_GID` — число из команды `getent group asterisk | cut -d: -f3`
  (сервис входит в группу `asterisk`, чтобы читать и чистить записи в `/srv/recordings`).

Запуск:

```
sudo docker compose up -d --build
```

Команда собирает образ, поднимает базу, создаёт таблицы и запускает сервис. Проверка:

```
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ: `{"status":"ok","db":"ok","ami":"connected"}`. После тестового звонка
`curl http://127.0.0.1:8000/api/events` покажет его события.

Сервис слушает только `127.0.0.1:8000`, база — только `127.0.0.1:5432`. Наружу ничего не открыто.
